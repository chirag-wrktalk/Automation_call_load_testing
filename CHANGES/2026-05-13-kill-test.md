# Change: Forced Test Termination (Kill Button)

**Date:** 2026-05-13  
**Branch:** feat/kill-test  
**Author:** AI Agent  

## User Ask
Implement a kill test button on the left rectangular card. The kill button should absolutely kill the test created with all its children's threads etc. 100% cleanup.

## Current Implementation
- **Wait for Completion**: Users previously had to wait for the test to finish naturally or manually kill the dashboard process.
- **Graceful Stop (Deprecated)**: Internal logic used `SIGINT`, which some processes might ignore or take time to clean up.

## New Implementation
- **Absolute Termination (SIGKILL)**:
    - Updated the `/stop` endpoint in `server.js` to use `SIGKILL` on the entire process group (`-pid`).
    - This forces an immediate exit for the test runner, all worker threads, and orphaned browser instances, ensuring 100% resource cleanup.
- **Danger UI Action**:
    - Added a **Kill Test (Force Stop)** button to the control panel.
    - Styled with a high-visibility red aesthetic to indicate a destructive action.
    - Integrated with a confirmation dialog to prevent accidental triggers.
- **State Management**:
    - The button only appears when a test is in progress.
    - Automatically hides and resets the dashboard state once termination is confirmed.

## New Introductions
- **`SIGKILL` Group Signal**: Guaranteed termination of all descendants regardless of their internal state.
- **Kill Test UI Component**: A dedicated escape hatch for stuck or unwanted test runs.

## Decisions & Trade-offs
- **Forced vs Graceful**: Chose `SIGKILL` over `SIGINT` to satisfy the "absolute kill" requirement, even though it bypasses normal process cleanup hooks (like saving final reports), as the priority is immediate resource release.
